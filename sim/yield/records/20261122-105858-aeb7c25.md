## Environment finding (why everything ran on the fleet)

The dispatch worker's own CPU (Intel Core Ultra 7 155H — AVX2/FMA, no
AVX-512) faults with `internal error -- illegal instruction` inside the
PSP103 OSDI model evaluation with the host ngspice-47 and the PDK fetch of
2026-11-20 (`~/share/pdk`, `fetched:0.3.0`); a one-transistor `op` on
`mos_tt` + `psp103.osdi` reproduces it. The batch fleet's image
(m6i.4xlarge worker, its own ngspice 47 + PDK) runs the identical decks
cleanly, so every run of this campaign — references and MC — was submitted
to the fleet. Local PSP simulation on this host class is broken until the
OSDI is rebuilt for it; not a klayout-tools gap (the fleet path is the
sanctioned one and works).

## DUT and measurement definitions

- DUTs: `layout/lvs/netlists/sg13g2_inv_1.spice` and
  `sg13g2_nand2_1.spice`, fresh per
  `python3 design/gen_netlists.py --config layout/example_config.json --out
  layout/lvs/netlists --check` (4 netlists fresh, run before the campaign).
  NAND2's B input is tied to VDD (switching arc A→Y).
- Measurement: `.meas tran` TRIG input at 0.6 V (50 % of 1.20 V) TARG
  output at 0.6 V; input `PULSE(0 1.2 2n 0.05n 0.05n 4n 10n)` (0.05 ns
  edges); output load 10 fF; `tran 2p 10n`; unit s.
  `inv_tpdlh` = A falls → Y rises; `inv_tpdhl` = A rises → Y falls; same
  for `nand_*` on the NAND's switching arc.
- Mismatch: PDK models, not assumed — `corners.process:
  ["mos_tt_mismatch"]` loads `sg13g2_moslv_mismatch.lib` (sigma params,
  e.g. `sg13g2_lv_nmos_delvto_mm = 0.0039`) and
  `sg13g2_moslv_mod_mismatch.lib` (per-instance `agauss` on `delvto`,
  `factuo`, `w`, `l`, Pelgrom 1/sqrt(m·l·w)). Devices: the cells' low-voltage
  `sg13_lv_nmos` / `sg13_lv_pmos` (the PDK ships mismatch models for both).
- `klt sim`'s per-family mismatch disclosure
  (`environment.monte_carlo.family_mismatch`, identical in both
  `mc-nominal.report.json` and `mc-knownbad.report.json`, with
  `family_mismatch_scan` covering the testbench and both DUT netlists and
  `not_scanned: []`) confirms `mosfet` is `active: true` — "MOS
  per-instance mismatch is active: every selected process section is a
  *_mismatch section (mos_tt_mismatch), which includes the agauss()
  mismatch subcircuits (see docs/cli/sim.md's 'Known-good mismatch
  mechanisms')." The two `active: null` entries (`capacitor` and `other`,
  each "not independently verified for PDK family 'sg13g2'") correspond to
  the testbench's ideal 10 fF load capacitors (`CL1`/`CL2`) and
  supply/stimulus voltage sources (`VSUP`/`VA1`/`VA2`), whose mismatch is
  irrelevant to row 0003-R1. The observed per-arc spread (stddev
  1.07–1.71 ps on 54–68 ps means, below) corroborates that the draws vary
  under `mos_tt_mismatch`.
