# sim/yield

Monte Carlo local-mismatch campaign evidence for proposed spec row 0003-R1
(`spec/0003-cell-delay-mismatch-spread.md`, issue #182): per-arc
propagation-delay yield of `sg13g2_inv_1` and `sg13g2_nand2_1` under the
PDK's mismatch models at the TT corner, via `klt sim` Monte Carlo + `klt
yield`. The campaign record is
`records/20261122-105858-aeb7c25.md`; the `klt yield` report it grades
against is `yield.json`.

Layout (all inputs and outputs are committed together — nothing here is
regenerated by CI):

- `testbench-cells.spice` — nominal bench: both DUTs from
  `layout/lvs/netlists/` (`.include`d relatively), 0.05 ns input edges,
  10 fF loads, 50 % VDD thresholds.
- `testbench-stock-inv.spice` — the stock PDK inverter (row-12 benchmark
  reference) in the same stimulus shape; `.include`s the PDK cell file via
  `$PDK_ROOT`, so a local replay needs `$PDK_ROOT` exported (fleet runs
  resolve it on the worker).
- `testbench-cells-knownbad.spice` + `dut-knownbad/` — the deterministic
  negative control: same measurement nodes, every DUT channel width halved
  (seeded defect). Fixtures only, never library views.
- `requests/` — the four `klt sim` request documents (reference runs use
  `mos_tt`; MC runs use `mos_tt_mismatch` with recorded seed and n=400).
- `reports/` — the four unedited `klt sim --format json` responses.
- `limits.json` — max = 1.10 x each arc's nominal reference value,
  `target_yield` 0.99, `spec_row` `0003-R1` (derivation in the spec
  record).
- `samples.json` — `klt yield-samples` derivation (nominal + control).
- `yield.json` — the `klt yield` report (yield, CI, Cpk, sample-size
  verdict, negative-control verdict).

## Replay

From this directory (the requests resolve their netlists relative to
themselves). Batch submits carry `--wait-for-capacity 600` (host rule).
`klt yield` needs the `yield` extra; the dispatch host's shared env does
not install it, so the analysis ran in a throwaway env — the sanctioned
path per the worker host rules, no host-wide tool change.

```bash
# 0. DUT freshness (from the repo root)
python3 design/gen_netlists.py --config layout/example_config.json \
    --out layout/lvs/netlists --check

# 1. deterministic references (single corner; explicit batch so the
#    worker resolves $PDK_ROOT/osdi and models.pdk on its own image)
klt sim requests/ref-nominal.request.json --format json \
    --backend batch --wait-for-capacity 600 > reports/ref-nominal.report.json
klt sim requests/ref-stock.request.json --format json \
    --backend batch --wait-for-capacity 600 > reports/ref-stock.report.json

# 2. Monte Carlo campaigns (n=400 each; seeds recorded in the requests)
klt sim requests/mc-nominal.request.json --format json \
    --backend batch --wait-for-capacity 600 > reports/mc-nominal.report.json
klt sim requests/mc-knownbad.request.json --format json \
    --backend batch --wait-for-capacity 600 > reports/mc-knownbad.report.json

# 3. derive the sample set (no native extension needed)
klt yield-samples reports/mc-nominal.report.json \
    --negative-control reports/mc-knownbad.report.json \
    --description 'seeded defect: every DUT channel width halved (drive roughly halved); expected effect: every arc delay far past the 1.10x-nominal limit' \
    --format json > samples.json

# 4. grade against the limits (needs the yield extra)
uvx --from "klayout-tools[yield]" klt yield samples.json \
    --limits limits.json --format json > yield.json
```

Re-deriving `samples.json` after either report changes also moves the
content hash a signoff citation pins (the derivation records both sources'
hashes); re-run step 3 whenever a report is re-run. Limits come from the
nominal reference (step 1), never from the MC result: `max = 1.10 x` the
reference value, by the spec record's derivation.

Note: the reports' `environment.remote`/batch fields name the fleet jobs the
committed responses came from (see the campaign record). A local replay on a
host whose CPU cannot run the PDK's PSP103 OSDI will fault — run the fleet
path above (campaign record, "Environment finding").
