# sim

Testbenches and PVT corner results (ngspice). harness/ carries the PVT corner definitions, evidence schema and record-id helpers (see harness/README.md). Simulation runs through `klt` (see characterize/), not a local ngspice runner.

## characterize/

Drives `klt characterize` and appends the raw per-arc delay / transition /
energy tables as an evidence record under
`sim/characterize/records/<record-id>.md`, using the harness record-id scheme
(`allocate_record_id`). Each record carries the slew and load axes, per-arc
values, the klt version and provenance, and the repo commit. Re-running mints a
new id; nothing is overwritten. Liberty formatting is always `klt`'s, never this
package's.

Two modes. The default **baseline leg** characterizes one existing
`sg13g2_stdcell` cell — the benchmark denominator of
`spec/0001-target-specification.md` ("Baseline Liberty") — and writes no
Liberty: it records measurements only.

```
python3 -m sim.characterize --pdk-dir <ihp-sg13g2 dir> [--backend local|batch]
python3 -m unittest sim.characterize.tests.test_request
```

Library view (spec row 9): `--library` characterizes every cell of
`layout/example_config.json` (SPICE regenerated by `design/gen_netlists.py` from
that same config) into ONE `klt characterize` `cells` request. `klt` writes the
committed `views/sg13g2_stdcells_tt_1p20v_25c.lib` (handed to it as `--lib`);
this package writes the `.lib.provenance` sidecar beside it (see
`views/README.md`) and appends one evidence record:

```
python3 -m sim.characterize --library --pdk-dir <ihp-sg13g2 dir>
```

One corner per invocation (TT/1.20 V/25 C by default). FF/SS are one
invocation per corner with `--backend batch`, never a local loop.

  `sg13g2_inv_4`, `sg13g2_nand2_1`), TT/1.20 V/25 C, 5x5 grid, five arcs, local

The local run needs ngspice >= 44 for the OSDI v0.4 PSP103 models. The request
preloads `psp103.osdi` (the module the PDK's `psp103va` model cards bind to),
not `psp103_nqs.osdi`. FF/SS corners are not yet run (batch only).
